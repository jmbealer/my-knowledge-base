## 3.3 Explain disaster recovery (DR) concepts

**DR Metrics**: *Measurements used* to evaluate disaster recovery readiness.

- **Recovery Point Objective (RPO)**: *Maximum tolerable data loss* following a disaster.
  - **Data Age**: *Maximum acceptable age* of recovered backup files.
            - **RPO (Recovery Point Objective)**: Max acceptable data loss.
- **Recovery Time Objective (RTO)**: *Maximum time allowed* to restore services.
  - **Downtime Limit**: *Targeted duration* to resume business continuity.
            - **RTO (Recovery Time Objective)**: Max downtime after disaster.
- **Mean Time to Repair (MTTR)**: *Average time to fix* a failed device.
  - **Repair Efficiency**: *Measure of speed* returning system to normal.
            - **MTTR**: Time to repair failures.
- **Mean Time Between Failures (MTBF)**: *Average time before* a component fails.
  - **System Reliability**: *Calculated lifespan* of component between failure events.
            - **MTBF**: Time between failures.

- **Backup Types**: *Different methods* for creating data copies.
  - **Full Backup**: *Complete backup* of all data.
  - **Incremental Backup**: *Backup of data changed* since last backup.
  - **Differential Backup**: *Backup of data changed* since last full backup.
  - **Offsite Backup**: *Storing backups* at a geographically separate location.

**DR Sites**: *Locations used* for recovering data and operations.

- **Disaster Recovery (DR)**: *Procedures for restoring* systems after failure.
- **Cold Site**: *Empty backup facility* requiring equipment setup.
  - **Infrastructure Only**: *Basic power and networking* without server hardware.
            - **Cold Site**: Infrastructure only, slowest recovery.
- **Warm Site**: *Partially equipped* backup site, not fully active.
  - **Partial Configuration**: *Pre-configured services* with delayed operational readiness.
            - **Warm Site**: Some equipment, faster setup.
- **Hot Site**: *Fully operational* backup site ready immediately.
  - **Mirror Site**: *Real-time synchronization* for immediate failover capability.
            - **Hot Site**: Fully equipped, instant recovery.

**High-Availability Approaches**: *Strategies for maintaining* continuous network service availability.

- **Active-Active**: *Redundant systems* simultaneously handling network traffic.
  - **Load Distribution**: *Simultaneous operation* maximizing throughput and performance.
            - **Active-Active**: Both systems share load.
- **Active-Passive**: *Backup system waiting* until primary system fails.
  - **Standby Mode**: *Ready system taking over* primary roles immediately.
            - **Active-Passive**: One system on standby.

- **Hardware Redundancy**: *Duplicate physical components* preventing single point failure.
- **Link Redundancy**: *Multiple network connections* providing failover paths.
- **Server Clustering**: *Group of servers* working together as single system.

**Testing**: *Assessing effectiveness* of disaster recovery and availability.

- **Tabletop Exercises**: *Theoretical drills* to test disaster response plans.
  - **Scenario Simulation**: *Discussion-based decision making* and gap identification.
            - **Tabletop Exercises**: Simulate and review plans.
- **Validation Tests**: *Practical assessments* confirming recovery procedures work.
  - **Process Execution**: *Actual restoration* to verify recovery objectives.
            - **Validation Tests**: Execute recovery procedures.

---

- **Business Continuity Metrics**:
  - **RPO (Recovery Point Objective)**: How much *data loss* is tolerable (measured in time since last backup).
  - **RTO (Recovery Time Objective)**: How much *downtime* is tolerable (time to get back online).
  - **MTTR (Mean Time to Repair)**: Average time to fix a failure.
  - **MTBF (Mean Time Between Failures)**: Average time a system runs before failing (reliability).
- **Backup Types**:
  - **Full**: Copies all data; slowest to back up, fastest to restore.
  - **Incremental**: Copies only data changed since the *last* backup; fastest to back up.
  - **Differential**: Copies all data changed since the last *full* backup.
- **DR Sites**:
  - **Hot Site**: Fully equipped and synchronized; nearly instant failover.
  - **Warm Site**: Equipment is present but needs configuration/data restore (hours/days).
  - **Cold Site**: Basic infrastructure (power/cooling) only; no equipment (days/weeks).
- **High Availability**:
  - **Active-Active**: Both systems handle traffic simultaneously (load balancing).
  - **Active-Passive**: One system is on standby and takes over if the primary fails.
  - **Redundancy**: Dual power supplies, NIC teaming, FHRP (HSRP/VRRP).

### DR Sites & Availability

- **Sites:** **Cold**, **Warm**, **Hot**.
- **High-Availability:** **Active-Active**, **Active-Passive**.

                    -
                    - ➤ Adds encryption and authentication to NTP for secure time sync.

        - ### Time Protocols
            - **NTP**: Syncs time over network.
            - **PTP**: High-precision local sync.
            - **NTS**: Adds security to NTP.

- **DHCP (Dynamic Host Configuration Protocol)**:
  - **DORA**: Discover, Offer, Request, Acknowledge.
  - **Relay/IP Helper**: Forwarding DHCP broadcasts across routers to a central server.
  - **Scope**: The range of IP addresses available to clients.
  - **Exclusions**: Specific IPs within a scope that are *not* handed out.
  - **Reservations**: Mapping a specific MAC address to a permanent IP.

  - **Record Types**:
    - **A**: Hostname to IPv4.

    - **MX**: Mail server.

    - **PTR**: IP to Hostname (Reverse lookup).
    - **NS**: Identifies authoritative name servers.
  - **Forward vs. Reverse Lookup**: Name-to-IP vs. IP-to-Name.
  - **Recursive vs. Iterative**: How a DNS server finds an answer.
  - **DNS Security**: **DNSSEC** (authenticity), **DoH** (DNS over HTTPS), **DoT** (DNS over TLS).
- **NTP (Network Time Protocol)**: Synchronizes clocks using a **Stratum** hierarchy (Stratum 0 is the atomic clock).

## 3.5 Compare and contrast network access and management methods

**Site-to-Site VPN**: *Connecting two entire networks* securely.

- **Network Interconnection**: *Linking geographically dispersed* offices over public internet.
- **Virtual Private Network (VPN)**: *Encrypted tunnel* over a public network.
                - **Site-to-Site VPN**
                    - Connects two networks across the internet.
                    - Typically used between office locations.
                    - Devices communicate as if on the same LAN.

**Client-to-Site VPN**: *Remote user connecting* securely to corporate network.

- **Remote Access**: *Individual users accessing* internal resources via internet.
- **Clientless VPN**: *Secure resource access* through a web browser.
- **Split Tunnel**: *Routing only corporate* traffic through VPN tunnel.
  - Split tunnel: Routing only specific traffic through VPN.
  - **Path Efficiency**: *Local internet traffic bypasses* the VPN gateway.
- **Full Tunnel**: *Routing all user traffic* through VPN gateway.
  - Full tunnel: Routing all traffic through VPN gateway.
  - **Complete Encryption**: *Ensuring all user traffic* is secured centrally.
                - **Client-to-Site VPN (Remote Access VPN)**
                    - User device connects securely to a network over the internet.
                    - Used for remote workers accessing corporate resources.
                    - **Clientless**
                        - Uses a web browser (e.g., SSL VPN).
                        - No dedicated VPN software needed.
                    - **Split Tunnel vs. Full Tunnel**
                        - **Split Tunnel**: Only corporate traffic goes through VPN; other traffic uses the local internet.
                        - **Full Tunnel**: All traffic routes through the VPN.

            - **Site-to-Site**: Connects networks.
            - **Client-to-Site**: Remote client to network.
            - **Clientless**: Browser-based access.
            - **Split Tunnel**: Corporate traffic through VPN only.
            - **Full Tunnel**: All traffic routed through VPN.

**Connection Methods**: *Techniques used* to access and manage devices.

- **Secure Shell (SSH)**: *Encrypted remote login* replacing insecure Telnet protocol.
  - RDP (Remote Desktop Protocol): GUI remote access protocol for Windows.
  - **Remote Management**: *Administrating network devices* from a distance securely.
- **Graphical User Interface (GUI)**: *Visual dashboard* for simplified device configuration.
- **Application Programming Interface (API)**: *Programmable interaction* for network automation and integration.
- **Console Connection**: *Direct physical access* for initial device setup.
                - **SSH (Secure Shell)**
                    - Encrypted command-line access to remote systems.
                - **Graphical User Interface (GUI)**
                    - Uses remote desktop tools (e.g., RDP, VNC) for visual interaction.
                - **API (Application Programming Interface)**
                    - Enables secure, programmatic interaction with systems and services.
                - **Console**
                    - Direct access to a device via physical serial or virtual terminal connection.
                    - Often used for initial configuration or recovery.

            - **SSH**: Secure remote CLI access.
            - **GUI**: Visual interface for management.
            - **API**: Programmable interaction.
            - **Console Connection**: Direct physical access.

**Jump Box/Host**: *Hardened intermediary* for accessing sensitive zones.
                - **Jump Box / Jump Host**
                    - A secured intermediary system used to access and manage devices in a protected network.
                    - Acts as a controlled gateway to limit direct access.
            - **Jump Box/Host**: Gateway to secure zones.

- **Security Gateway**: *Stepping stone* between different network trust levels.

**In-Band vs. Out-of-Band Management**: *Managing via primary* network or separate path.

- **In-Band Management**: *Administering devices* through the production data path.
- **Out-of-Band Management (OOB)**: *Dedicated management path* independent of data network.
  - **Outage Resilience**: *Ensuring device access* during primary network failure.
                - **In-Band vs. Out-of-Band Management**
                    - **In-Band**: Uses the primary network for management traffic (requires the network to be up).
                    - **Out-of-Band**: Uses a separate path for management (e.g., dedicated console port), useful when the main network is down.
            - **In-Band Management**: Uses production network.
            - **Out-of-Band Management**: Uses dedicated management network.

---

- **Remote Access VPN**:
  - **Client-to-Site**: Individual users (using software like AnyConnect).
  - **Site-to-Site**: Connecting two branch offices via encrypted tunnels.
  - **Full Tunnel**: *All* traffic goes through the VPN (more secure).
  - **Split Tunnel**: Only *corporate* traffic goes through the VPN; internet traffic goes local.
  - **Clientless (SSL VPN)**: Access via a web browser without special software.
- **Management Methods**:
  - **SSH (Secure Shell)**: Encrypted CLI access (Port 22).
  - **Console**: Physical serial connection (Out-of-band).
  - **Jump Box**: A hardened server used as a single point of entry into a secure zone.
  - **In-Band Management**: Managing devices over the same network they use for data.
  - **Out-of-Band (OOB) Management**: Using a dedicated network or console server for management, ensuring access even during a data network outage.
