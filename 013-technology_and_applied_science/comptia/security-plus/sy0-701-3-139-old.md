# 3.0 Security Architecture (18%)

## 3.1 Compare and contrast security implications of different architecture models

### Cloud Infrastructure Concepts
- **Cloud Computing Models:**
  - **IaaS (Infrastructure as a Service):** Provider manages hardware/data center; Customer manages OS, apps, and data.
  - **PaaS (Platform as a Service):** Provider manages OS and infrastructure; Customer focuses on application development.
  - **SaaS (Software as a Service):** Provider manages everything; Customer just uses the application (e.g., Google Workspace).
- **Deployment Models:**
  - **Public:** Shared resources available to anyone (e.g., AWS, Azure).
  - **Private:** Dedicated resources for a single organization.
  - **Hybrid:** Combination of public and private clouds (adds complexity in management).
  - **Community:** Shared by multiple organizations with common needs (e.g., government agencies).
- **Responsibility Matrix:** A document defining which security tasks are the provider's responsibility vs. the customer's (varies by model).
- **Infrastructure as Code (IaC):** Managing infrastructure via version-controlled machine-readable files (Puppet, Terraform). Enables consistent, rapid deployments.
- **Serverless (FaaS):** Apps broken into autonomous functions; the provider manages the OS and execution environment.
- **Microservices & APIs:** Breaking monolithic apps into small, independent services. APIs act as the "glue." Enhances scalability and fault isolation.

### Network Infrastructure
- **Physical Isolation (Air-gapped):** Disconnecting a system from all networks for maximum security.
- **Logical Segmentation:** Using VLANs to separate traffic on the same physical hardware.
- **Software-Defined Networking (SDN):**
  - **Data Plane (Infrastructure Layer):** Forwards/processes actual packets.
  - **Control Plane:** Manages routing and decisions for the data plane.
  - **Management Plane (Application Layer):** Used for configuration (SSH, GUI).
- **On-Premises:** Full control but high maintenance costs.
- **Centralized vs. Decentralized:** Centralized offers easier monitoring but creates single points of failure.

### Virtualization & Specialized Systems
- **Virtualization:** Multiple OSs on one host via a **Hypervisor** (Type 1: Bare metal; Type 2: Hosted).
- **Containerization:** Packaging apps with dependencies; uses the host OS kernel (Docker). Much more efficient than VMs.
- **IoT (Internet of Things):** Smart devices often with weak default security and limited update capabilities.
- **ICS/SCADA:** Systems for industrial control (power, water). Requires extreme segmentation (usually air-gapped).
- **RTOS (Real-time OS):** Highly deterministic OS for critical timing (robotics, flight controllers).
- **Embedded Systems:** Single-purpose hardware/software (smartwatches, HVAC controls).

### Architecture Considerations
- **Availability:** System uptime (Metric: % Uptime).
- **Resilience:** Ability to withstand and recover from failure (Metric: **MTTR** - Mean Time to Repair).
- **Cost:** Initial setup vs. ongoing maintenance (OpEx vs. CapEx).
- **Scalability/Elasticity:** Ability to grow or shrink resources on demand.
- **Risk Transference:** Moving risk to 3rd parties (Cybersecurity Insurance).
- **Ease of Deployment:** Orchestration and automation potential.

## 3.2 Given a scenario, apply security principles to secure enterprise infrastructure

### Infrastructure Considerations
- **Device Placement:** Positioning firewalls, sensors, and honeypots strategically.
- **Security Zones:** Segmenting by trust levels (External, DMZ/Screened Subnet, Internal).
- **Attack Surface:** Total entry/exit points; goal is to minimize them.
- **Failure Modes:**
  - **Fail-open:** Traffic continues to flow during failure (Prioritizes availability/safety).
  - **Fail-closed:** Traffic is blocked during failure (Prioritizes security).
- **Monitoring Modes:**
  - **Active (Inline):** IPS sits in the traffic path and can block in real-time.
  - **Passive (Tap/Monitor):** IDS receives a copy of traffic; can alert but not block immediately.

### Network Appliances
- **Jump Server:** Hardened entry point to access a more secure network zone.
- **Proxy Server:**
  - **Forward Proxy:** Sits in front of clients (hides IP, filters web content).
  - **Reverse Proxy:** Sits in front of web servers (load balancing, SSL decryption).
- **Intrusion Systems:** IDS (Detect/Alert) vs. IPS (Detect/Prevent).
- **Load Balancer:** Distributes traffic (Active/Active for performance, Active/Passive for failover).
- **Sensors:** Collect and analyze data for anomalies (SIEM inputs).

### Firewall Types
- **Web Application Firewall (WAF):** Operates at **Layer 7** (Application); prevents XSS, SQLi.
- **Unified Threat Management (UTM):** All-in-one appliance (AV, Firewall, Content Filtering).
- **Next-Gen Firewall (NGFW):** Deep packet inspection and application awareness.
- **Layer 4 vs Layer 7:** L4 filters by IP/Port; L7 filters by content/application data.

### Secure Communication
- **VPN (Virtual Private Network):** Encrypted tunnel over an insecure network.
  - **IPSec:** Tunnel mode (whole packet encrypted) vs. Transport mode (only payload).
  - **TLS/SSL VPN:** Browser-based or lightweight client; uses Port 443.
- **SD-WAN:** Centralized control for intelligent WAN routing.
- **SASE (Secure Access Service Edge):** Cloud-native merging of network (SD-WAN) and security services.

## 3.3 Compare and contrast concepts and strategies to protect data

### Data Types & Classifications
- **Types:** Regulated (PII, PHI, PCI), Trade Secrets, IP (Copyrights, Patents), Legal, Financial.
- **Classifications:** Sensitive, Confidential, Public, Restricted, Private, Critical.
- **IP Protection:**
  - **Copyright:** Creative works (70 years after death).
  - **Patent:** Inventions (20 years).
  - **Trademark:** Branding (10 years, renewable).

### General Data Considerations
- **Data States:**
  - **At Rest:** Stored on disk (Protected by Encryption).
  - **In Transit:** Moving over network (Protected by TLS/IPSec).
  - **In Use:** Loaded in RAM/being processed (Protected by Secure Enclaves/Isolation).
- **Data Sovereignty:** Data is subject to the laws of the country where it is located.
- **Geolocation:** Restricting access or storage based on physical location.

### Methods to Secure Data
- **Encryption:** One-way or two-way coding.
- **Hashing:** One-way integrity check (Passwords).
- **Masking:** Partial hiding (e.g., XXX-XX-1234).
- **Tokenization:** Replacing sensitive data with a random token (Credit card processing).
- **Obfuscation:** Making data unclear (Steganography).
- **Segmentation:** Isolating data access by network zones.
- **Permission Restrictions:** Using ACLs and the Principle of Least Privilege.

## 3.4 Explain the importance of resilience and recovery in security architecture

### High Availability (HA)
- **Redundancy:** Duplicate components to avoid single points of failure.
- **Load Balancing vs. Clustering:** LB distributes traffic; Clustering groups servers to act as one.

### Disaster Recovery Sites
- **Hot Site:** Fully functional duplicate; data is synchronized (Recovery in minutes).
- **Warm Site:** Hardware is there but needs configuration/data restored (Recovery in hours).
- **Cold Site:** Empty building with power/cooling; no hardware (Recovery in days/weeks).
- **Geographic Dispersion:** Placing sites in different regions to survive regional disasters.

### Testing & Backups
- **Testing:** Tabletop exercises (discussion), Failover (actual switch), Simulation.
- **Backups:**
  - **Frequency:** Daily/Weekly/Real-time.
  - **Storage:** Onsite (Fast recovery) vs. Offsite (Safe from local disaster).
  - **Encryption:** Essential for backup security.
  - **Snapshots:** Point-in-time image (common in VMs).
  - **Replication/Journaling:** Real-time data copying.

### Power & Capacity
- **Capacity Planning:** Ensuring enough People, Technology, and Infrastructure for a crisis.
- **Power Resilience:**
  - **UPS (Uninterruptible Power Supply):** Short-term battery for graceful shutdowns or gap bridging.
  - **Generators:** Long-term power replacement.
