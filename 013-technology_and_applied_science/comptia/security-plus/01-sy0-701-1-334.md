# 1.0 General Security Concepts (12%)

## 1.1 Compare and contrast various types of security controls

Security controls are safeguards or measures taken to reduce risk to assets (data, physical property, computer systems).

**Categories:**

- **Technical (Logical):** Controls implemented via software, hardware, or firmware systems.
  - **Examples:** Firewalls, encryption, Intrusion Detection Systems (IDS), antivirus, authentication mechanisms, BIOS/UEFI settings.
  - **Pros/Cons:** Automated and scalable, but vulnerable to technical failures or software bugs.
- **Managerial (Administrative):** Strategic risk governance through policies and procedures.
  - **Examples:** Risk assessments, security policies (AUP), hiring practices (background checks), security awareness training, vendor management.
  - **Pros/Cons:** Pivotal for strategic decision-making, but requires regular review and management commitment.
- **Operational:** Processes executed by people during daily operations.
  - **Examples:** Backup and recovery procedures, incident response, change management, physical security guards, awareness programs.
  - **Pros/Cons:** Addresses day-to-day human behavior, but vulnerable to human error and requires continuous oversight.
- **Physical:** Tangible, real-world measures protecting assets and safety.
  - **Examples:** Bollards, fences, locks, CCTV, security guards, access badges, fire suppression, motion sensors.
  - **Pros/Cons:** Protects against physical theft/damage, but does not protect against remote cyber threats.

**Control Types (Functional):**

- **Preventive:** Stops a security incident before it occurs (proactive).
  - **Examples:** Firewall rules, locked doors, strong password policies, encryption, guard shacks.
- **Deterrent:** Discourages intrusion by warning of negative consequences or increasing perceived risk.
  - **Examples:** Warning signs ("No Trespassing"), visible security cameras, application splash screens, threat of demotion.
- **Detective:** Identifies and records events during or after occurrence (reactive).
  - **Examples:** Audit logs, security alarms, IDS, motion detectors, regularly patrolling guards.
- **Corrective:** Mitigates damage and restores systems after incidents (correcting the problem).
  - **Examples:** Restoring from backups, antivirus quarantining/removing malware, patching a vulnerability after a breach, fire extinguishers.
- **Compensating:** Alternative substitute when primary control is not feasible or sufficient.
  - **Examples:** If you can't encrypt an old system, use strict physical isolation (locked room); using a generator during a power outage.
- **Directive:** Mandates compliance through administrative rules, regulations, or guidance.
  - **Examples:** Acceptable Use Policy (AUP), security awareness training, signs ("Authorized Personnel Only").

---

> **Exam Tip:** Be prepared to categorize a specific control by both Category and Type. (e.g., A security guard is both a *Physical* category and can be *Preventive*, *Deterrent*, or *Detective*).

## 1.2 Summarize fundamental security concepts

Confidentiality, Integrity, and Availability (CIA)
The fundamental goals of cybersecurity (sometimes called the AIC Triad).

- **{{CIA Triad}}**: Core model for *information security policy*.

- **Confidentiality:** Preventing unauthorized access or disclosure of data.
  - **Techniques:** Encryption, access controls, MFA.
- **Integrity:** Ensuring data remains accurate and unaltered.
  - **Techniques:** Hashing, digital signatures, file permissions, certificates.
- **Availability:** Ensuring data and systems are accessible when needed.
  - **Techniques:** Redundancy (RAID, Load Balancing), fault tolerance, patching, backups.

**Non-repudiation:** Proving a subject performed an action undeniably.
 Non-repudiation

Guarantees that a subject cannot deny having performed an action.

- **Techniques:** Digital signatures (signed with a private key), logging systems.
- **Example:** A digitally signed email provides proof of origin and proof that the sender sent it.

Authentication, Authorization, and Accounting (AAA)

- **AAA:** Framework for verifying, granting, and tracking access.
- **{{AAA Framework}}**: Model for *controlling access to computer resources*.
- **Authenticating people:** Verifying a human user's claimed identity.
- **Authenticating systems:** Verifying a device or service's identity.
- **Authorization models:** Structured rules determining access rights and permissions.
- **Identification:** Claiming an identity (e.g., username).
- **Authentication:** Proving you are who you say you are ("Who are you?").
  - **Authenticating People:** Passwords, biometrics (fingerprint/face), smartcards, OTP apps.
  - **Authenticating Systems:** Digitally signed certificates, keys.
- **Authorization:** Determining access rights and permissions ("What can you do?").
  - **Authorization Models:** Structured rules like Role-Based Access Control (RBAC), Attribute-Based Access Control (ABAC), Mandatory Access Control (MAC).
- **Accounting:** Tracking and recording activities for auditing ("What did you do?").
  - **Techniques:** Log review, audit trails, monitoring access attempts.

**Gap Analysis:** Comparing current security against the desired state.
Comparing the current security posture against the desired state or industry standards.

- **Goal:** Identify weaknesses ("gaps") and create action plans to reach the desired baseline (e.g., NIST, ISO).

**Zero Trust:** "Never trust, always verify" security model.  
A holistic security model based on the principle: **"Never trust, always verify."**

- **{{Least Privilege}}**: Granting only the *minimum necessary access*.
- **{{Assume Breach}}**: Operating as if *attackers are already present*.

- **Control Plane (The "Brain"):** Orchestrates access decisions and policy management.
  - **Adaptive identity:** Authentication requirements adjust based on risk context.
  - **Adaptive Identity:** Authentication requirements adjust based on risk context (location, IP, device health).
  - **Threat scope reduction:** Minimizing the potential attack surface.
  - **Policy-driven access control:** Access granted strictly based on defined rules.
  - **Policy Engine:** Component making the decision to grant access.
  - **Policy Engine:** Evaluates access requests against policies (the decision maker).
  - **Policy Administrator:** Component establishing the connection based on decisions.
  - **Policy Administrator:** Establishes/terminates the connection based on the Engine's decision.
- **Data Plane (The "Action"):** Where actual application data flow occurs.
  - **Implicit trust zones:** Trusted network areas; eliminated in Zero Trust.
  - **Implicit Trust Zones:** Trusted network areas; these are **eliminated** in a Zero Trust architecture.
  - **Subject/System:** The entity requesting access to a resource.
  - **Policy Enforcement Point:** Intercepts traffic to enforce access decisions.
  - **Policy Enforcement Point (PEP):** Gatekeeper that intercepts traffic to enforce decisions (e.g., firewall, gateway).

- **Core Principles:** No implicit trust (even inside the network), assume breach, least privilege.

**Physical security:** Protecting assets from tangible, real-world threats.

- **Bollards:** Sturdy posts preventing vehicle ramming attacks.
- **Access control vestibule:** Double-door system restricting entry to prevent tailgating.
- **Fencing:** Perimeter barrier defining boundaries and deterring entry.
- **Video surveillance:** Monitoring and recording visual activity (CCTV).
- **Security guard:** Human presence for monitoring and intervention.
- **Access badge:** Physical token granting entry via a reader.
- **Lighting:** Illuminating areas to deter and detect intruders.
- **Sensors:** Devices detecting physical environmental changes.
  - **Infrared:** Detects motion via heat signature changes.
  - **Pressure:** Detects weight application on a surface.
  - **Microwave:** Detects movement via radio wave reflection.
  - **Ultrasonic:** Detects motion via high-frequency sound waves.

- **Barriers:** Bollards (prevent vehicle ramming), fencing (perimeter barrier), access control vestibules (mantraps/double-door systems to prevent tailgating).
- **Monitoring:** Video surveillance (CCTV), security guards.
- **Access:** Access badges, lighting (deterrent/facial recognition helper).

**Deception and disruption:** Techniques to confuse, trap, or slow attackers.

- **Honeypot:** Single decoy system luring attackers away.
- **Honeynet:** Network of decoys simulating a real environment.
- **Honeyfile:** Decoy file triggering alerts when accessed.
- **Honeytoken:** Fake data element tracking attacker activity.

## 1.3 Explain the importance of change management processes and the impact to security

Change management ensures modifications (software upgrades, firewall changes) are structured and secure to avoid introducing vulnerabilities.

- **{{Change Management}}**: Process to *control lifecycle of system changes*.
  - **{{Separation of Duties}}**: Dividing tasks to *prevent error or fraud*.
  - **{{Rollback}}**: Ability to *revert to previous state* upon failure.

Business Processes Impacting Security Operation

- **Approval Process:** Formal authorization required before implementing changes.
- **Ownership:** Individual or entity accountable for a specific asset.
- **Stakeholders:** Individuals interested in or affected by the change.
- **Impact Analysis:** Assessing potential consequences before implementing a change.
- **Test Results:** Proof that changes function correctly without errors.
- **Backout Plan:** Procedure to revert changes if implementation fails.
- **Maintenance Window:** Scheduled timeframe authorized for performing system changes.
- **Standard Operating Procedure (SOP):** Step-by-step instructions for routine tasks.

Technical Implications

- **Allow lists/Deny lists:** Explicitly permitting or blocking specific traffic or software.
- **Restricted Activities:** High-risk actions prohibited during specific times.
- **Downtime:** Period when a system or service is unavailable.
- **Service Restart:** Stopping and starting background system processes.
- **Application Restart:** Closing and reopening software to apply updates.
- **Legacy Applications:** Outdated software still used for business needs.
- **Dependencies:** Components requiring other components to function correctly.

Documentation

- **Updating Diagrams:** Revising visuals to match the current network state.
- **Updating Policies/Procedures:** Modifying rules to reflect new operational realities.

**Version Control:** System tracking and managing changes to files.

- Critical for forensics

## 1.4 Explain the importance of using appropriate cryptographic solutions

**Public Key Infrastructure (PKI):** Framework managing digital keys and certificates.

- **Public Key:** Sharable key used for encryption or verification.
- **Private Key:** Secret key used for decryption or signing.
- **Key Escrow:** Storing keys with a third party for recovery.
- **{{Trust Chain}}**: Path of trust from *root CA to end-entity*.

**Encryption:**

- **Level:**
  - **Full-disk:** Encrypts the entire physical drive and OS.
  - **Partition:** Encrypts specific logical sections of a drive.
  - **File:** Encrypts individual files rather than whole systems.
  - **Volume:** Encrypts a specific logical drive or container.
  - **Database:** Encrypts the entire database structure and contents.
  - **Record:** Encrypts specific rows or entries in databases.
- **Transport/Communication:** Encrypting data moving across a network (data-in-transit).
- **Asymmetric:** Uses key pairs: one public, one private.
- **Symmetric:** Uses the same key for encryption and decryption.
- **Key Exchange:** Secure method for parties to swap keys.
- **Algorithms:** Mathematical formulas performing the encryption process.
- **Key length:** Number of bits determining the key's strength.
- **{{Diffie-Hellman (DH)}}**: Protocol to *exchange keys over insecure channels*.
- **{{Perfect Forward Secrecy (PFS)}}**: Past sessions remain secure *even if key is compromised*.
- **{{Entropy}}**: Measure of *randomness* in cryptographic material.

**Tools:**
 Cryptographic Tools

- **Trusted Platform Module (TPM):** Motherboard chip storing keys and ensuring integrity.
- **Hardware Security Module (HSM):** Dedicated physical appliance for secure key management.
- **Key Management System:** Software platform for managing the key lifecycle.
- **Secure Enclave:** CPU-isolated area protecting sensitive memory and code.

**Obfuscation:** Making code or data difficult to understand.

- **Steganography:** Hiding secret data within innocent-looking files.
- **Tokenization:** Replacing sensitive data with non-sensitive unique symbols.
- **Data Masking:** Hiding specific characters of data for display.

**Hashing:** One-way conversion of data to fixed string.

- **{{Collision}}**: distinct inputs *producing the same hash*.
**Salting:** Adding random data to passwords before hashing.
**Digital Signatures:** Cryptographic proof of message origin and integrity.
**Key Stretching:** Slowing down processing to strengthen weak keys.
**Blockchain:** Decentralized, immutable chain of transaction blocks.
**Open Public Ledger:** Transparent transaction record accessible to everyone.

**Certificates:** Digital document binding a key to identity.

- **Certificate authorities (CA):** Trusted entities that issue and verify certificates.
- **Certificate revocation lists (CRL):** List of invalid certificates published by CA.
- **OCSP:** Real-time protocol checking if certificate is valid.
- **Online Certificate Status Protocol (OCSP):** Real-time valid-check; **OCSP Stapling** lets the server cache the status to save resources.
  - **{{OCSP Stapling}}**: Server caches OCSP response to *reduce CA load*.
- **Self-signed:** Signed by the creator, not a CA.
- **Third-party:** Signed by a trusted external Certificate Authority.
- **Root of trust:** The ultimate, foundational trust anchor in PKI.
- **CSR generation:** Request sent to CA to apply for certificate.
- **Certificate Signing Request (CSR):** Sent to CA to apply for a certificate.
- **Wildcard:** Certificate covering a domain and all subdomains.
