# 2.0 Threats, Vulnerabilities, and Mitigations (22%)

## 2.1 Compare and contrast common threat actors and motivations

A **threat actor** (or malicious actor) is an entity responsible for an event that impacts the safety or security of another entity.

### Threat Actors
- **Nation-state:** Government-sponsored actors.
  - **Attributes:** Highest sophistication, massive resources/funding, constant attacks.
  - **Focus:** National security, critical infrastructure (utilities, military), espionage, or war. Often classified as **Advanced Persistent Threats (APTs)**.
- **Unskilled Attacker:** Often called "Script Kiddies."
  - **Attributes:** Low technical skill, uses pre-made tools/scripts, limited resources.
  - **Focus:** "The hunt," disruption, or data exfiltration. They look for "low-hanging fruit."
- **Hacktivist:** A hacker with a political or social purpose.
  - **Attributes:** Can be remarkably sophisticated, often external but can infiltrate as an insider.
  - **Focus:** Political agendas, social change, website defacement, or releasing private documents to cause embarrassment.
- **Insider Threat:** A threat from within the organization (employee, contractor, partner).
  - **Attributes:** Institutional knowledge, legitimate access, medium sophistication.
  - **Focus:** Revenge (disgruntled employee) or financial gain. Can be malicious or unintentional (human error).
- **Organized Crime:** Professional criminals working for profit.
  - **Attributes:** Highly sophisticated, well-funded, structured hierarchy (specialized roles for hacking, selling data, support).
  - **Focus:** Financial gain, ransomware, identity theft, and fraud.
- **Shadow IT:** Unauthorized systems/apps used without IT department approval.
  - **Attributes:** Often non-malicious but bypasses security controls, creating vulnerabilities.
  - **Focus:** Innovation or convenience (e.g., using personal cloud storage for work files).

### Attributes of Actors
- **Internal/External:** Is the actor "inside the house" or outside trying to get in?
- **Resources/Funding:** Ranges from no money (unskilled) to unlimited government budgets (nation-state).
- **Level of Sophistication/Capability:** Ability to write custom malware vs. blindly running scans.

### Motivations
- **Data exfiltration:** Stealing data for sale or leverage.
- **Espionage:** Spying (common in nation-state/corporate rivalry).
- **Service disruption:** Causing chaos or protesting (DoS attacks).
- **Blackmail:** Threatening to release data unless paid (Ransomware/Extortion).
- **Financial gain:** Direct monetary theft or fraud.
- **Philosophical/Political/Ethical:** Acting on beliefs (Hacktivism/Whistleblowing).
- **Revenge:** Retaliation for a perceived wrong.

## 2.2 Explain common threat vectors and attack surfaces

A **Threat Vector** (or Attack Vector) is the method/path used to gain access or infect a target. The **Attack Surface** is the sum of all points where an unauthorized user can try to enter or extract data.

### Message-based Vectors
- **Email:** Phishing links/attachments.
- **SMS (Smishing):** Links sent via text message.
- **Instant Messaging (IM):** Malware delivered through real-time chat.

### Image-based Vectors
- **SVG (Scalable Vector Graphics):** Images described in XML can contain HTML injection or malicious JavaScript.
- **Steganography:** Hiding malicious code within innocent-looking image files.

### File-based Vectors
- **PDFs:** Can contain embedded malicious objects.
- **ZIP/RAR:** Compression hides malware from simple scans.
- **Office Documents:** Macros and add-ins can execute malicious code.

### Voice Call (Vishing)
- **Vishing:** Phishing over the phone or voicemail (caller ID spoofing is common).

### Removable Devices
- **USB Flash Drives:** Can infect air-gapped networks, act as "hacker keyboards" (Rubber Ducky), or exfiltrate data physically.

### Vulnerable Software
- **Client-based:** Vulnerabilities in installed executables requiring constant patching.
- **Agentless:** Compromised software on the server affects all users without local installs.

### Unsupported Systems (End-of-Life)
- Systems no longer receiving security patches (e.g., Windows XP). A single unpatched system can be an entry point.

### Unsecure Networks
- **Wireless:** Outdated protocols (WEP, WPA) or rogue access points.
- **Wired:** Interfaces without 802.1X protection.
- **Bluetooth:** Implementation flaws allowing eavesdropping or unauthorized access.

### Open Service Ports & Default Credentials
- **Open Ports:** Every active TCP/UDP port is an opportunity (e.g., Port 80, 443).
- **Default Credentials:** Many routers/IOT devices have "admin/admin" defaults that must be changed.

### Supply Chain
- **MSPs:** Gaining access to multiple customer networks via a single provider breach.
- **Vendors/Suppliers:** Counterfeit hardware with backdoors or compromised software updates (e.g., SolarWinds attack).

### Human Vectors (Social Engineering)
- **Phishing:** Spoofing and misdirection (check for spelling/URL errors).
- **Business Email Compromise (BEC):** Spoofing executives to authorize fraudulent wire transfers.
- **Pretexting:** Creating a character and a story to trap a victim (e.g., "I'm with the help desk").
- **Impersonation:** Pretending to be someone of higher rank or a "buddy."
- **Watering Hole:** Infecting a 3rd-party website that the target group frequently visits.
- **Typosquatting:** Registering domains similar to legitimate ones (URL Hijacking).
- **Brand Impersonation:** Mimicking famous brands to trick users into pop-ups/malware.

## 2.3 Explain various types of vulnerabilities

### Application Vulnerabilities
- **Memory Injection:** Adding code into the memory of a running process to hide malware or escalate privileges (e.g., **DLL Injection**).
- **Buffer Overflow:** Overwriting a memory buffer to spill into other areas; developers must use **bounds checking** to prevent this.
- **Race Conditions:** Timing-based bugs where the outcome depends on the sequence of events.
  - **TOCTOU (Time-of-Check to Time-of-Use):** Something changes between the system checking a resource and actually using it.
- **Malicious Update:** Fake updates that weaken security; prevented by **code signing**.

### OS & Web-based Vulnerabilities
- **OS-based:** Complex codebases with millions of lines often have hidden flaws (Remote Code Execution, Privilege Elevation).
- **Web-based:**
  - **SQL Injection (SQLi):** Inserting SQL commands into input fields to manipulate the database (e.g., `' OR '1'='1'`).
  - **Cross-site Scripting (XSS):** Injecting scripts into trusted websites to steal cookies/sessions.
    - **Reflected (Non-persistent):** Script is in user input (e.g., a search box) and reflected back.
    - **Stored (Persistent):** Script is saved on the server (e.g., a forum post) and affects all visitors.

### Hardware & Virtualization
- **Hardware:** Firmware vulnerabilities, End-of-life (EOL) gear, or legacy hardware that cannot support new security measures.
- **Virtualization:**
  - **VM Escape:** Breaking out of a VM to interact with the host system.
  - **Resource Reuse:** Sensitive data remaining in memory/storage and accessed by other processes.

### Cloud & Supply Chain
- **Cloud-specific:** Misconfigurations (public S3 buckets), insecure APIs, account hijacking.
- **Supply Chain:** Risks from Service/Hardware/Software providers (e.g., backdoors in chips).

### Cryptographic Vulnerabilities
- **Weak Algorithms:** Using DES or MD5 (subject to collisions).
- **Poor Implementation:** Programming errors like buffer overflows in encryption code.
- **Key Management:** Improperly stored or generated keys.

### Misconfiguration & Mobile
- **Misconfiguration:** Using default settings or leaving unnecessary services enabled.
- **Mobile Device:** Side-loading (untrusted apps), Jailbreaking/Rooting (removing OS restrictions).

### Zero-day
- A vulnerability unknown to the vendor with "zero days" to fix before exploitation begins.

## 2.4 Given a scenario, analyze indicators of malicious activity

### Malware Attacks
- **Ransomware:** Sudden file encryption, ransom notes, changed extensions.
- **Trojan:** Disguised as legitimate software; unauthorized system changes.
- **Worm:** Rapid independent spread across the network; high bandwidth usage.
- **Spyware:** Keyloggers, unauthorized surveillance (camera/mic), pop-ups.
- **Bloatware:** Unwanted pre-installed apps slowing down systems.
- **Virus:** Attaches to files; corrupts data or alters program behavior.
- **Logic Bomb:** Triggered by a specific date/time or event (e.g., employee termination).
- **Rootkit:** Clandestine access; hides itself from the OS and scanners.

### Network Attacks
- **DDoS:** Overwhelming traffic (SYN Floods, UDP Floods).
  - **Amplified/Reflected:** Using spoofed IPs to force 3rd-party servers to flood the victim.
- **DNS Attacks:** Cache Poisoning (Spoofing), DNS Hijacking, or DNS Tunneling (exfiltrating data in DNS queries).
- **On-path (MitM):** Eavesdropping, session hijacking, or **SSL Stripping** (downgrading HTTPS to HTTP).
- **Credential Replay:** Reusing captured credentials (prevented by MFA or salts).

### Application Attacks
- **Privilege Escalation:**
  - **Vertical:** Regular user becomes Admin.
  - **Horizontal:** User accesses another user's data.
- **Forgery:** Cross-site Request Forgery (CSRF) or Server-side Request Forgery (SSRF).
- **Directory Traversal:** Using `../` sequences to access files outside the web root.

### Indicators of Compromise (IoC)
- **Account Lockout:** Multiple failed login attempts.
- **Concurrent Session Usage:** One account logged in from multiple places.
- **Impossible Travel:** Logins from distant locations in a short timeframe.
- **Resource Consumption:** High CPU/Memory usage without cause.
- **Out-of-cycle Logging:** Logs generated at odd hours or deleted (Missing logs).

## 2.5 Explain the purpose of mitigation techniques used to secure the enterprise

### Network & Access Mitigations
- **Segmentation:** Dividing networks to isolate breaches (VLANs).
- **Access Control:** Using **ACLs** and **Permissions** to regulate access.
- **Application Allow List:** Strict control where only approved apps run.
- **Isolation/Sandboxing:** Running untrusted code in a "safe space."

### Hardening Techniques
- **Hardening:** Reducing the attack surface by securing configurations.
- **Patching:** Regularly updating to fix vulnerabilities.
- **Encryption:** Protecting data-at-rest and data-in-transit.
- **Monitoring:** SIEM, Log Aggregation, and alert response.
- **Least Privilege:** Granting minimum necessary access.
- **Configuration Enforcement:** Standardizing settings via Group Policy or automation.
- **Decommissioning:** Securely wiping/destroying assets (Sanitization).

### Host-based Mitigations
- **Host-based Firewall/HIPS:** Machine-level traffic and activity control.
- **Disabling Ports/Protocols:** Closing unnecessary entry points.
- **Default Password Changes:** Essential first step for any new device.
- **Endpoint Protection (EPP/EDR):** Real-time threat detection and removal on the device.
