# 4.0 Security Operations

## 4.1 Given a scenario, apply common security techniques to computing resources

**Secure baselines**

- **Establish:** Define minimum security requirements for a system (e.g., standard OS settings, required patches).
- **Deploy:** Use automation (Group Policy, MDM) to apply baselines across thousands of devices.
- **Maintain:** Regularly audit and update baselines as new vulnerabilities or software versions emerge.

**Hardening targets**

- **Mobile devices**
- **Workstations**
- **Switches**
- **Routers**
- **Cloud infrastructure**
- **Servers**
- **ICS/SCADA:** Require extreme segmentation and often air-gapping.
- **Embedded systems**
- **RTOS**
- **IoT devices**
- **IoT:** Change default passwords and isolate on separate VLANs.

- **Workstations/Servers:** Disable unnecessary services, close unused ports, use host-based firewalls and EDR.
- **Network Devices (Routers/Switches):** Change default credentials, use SSH instead of Telnet, disable unused ports.
- **RTOS/Embedded:** Run minimum services and use secure communication protocols.

**Wireless devices**

- **Installation considerations**
  - **Site surveys**
  - **Site Surveys:** Using heat maps to identify signal strength and interference.
  - **Heat maps**

**Mobile solutions**

- **Mobile device management (MDM)**
- **Deployment models**
  - **BYOD (Bring Your Own Device):** Employee-owned; difficult to secure but saves costs.
  - **COPE (Corporate Owned, Personally Enabled):** Organization buys and controls the device but allows personal use.
  - **CYOD (Choose Your Own Device):** Similar to COPE but with a choice of hardware.
- **Connection methods**
  - **Cellular**
  - **Wi-Fi**
  - **Bluetooth**

**Wireless security settings**

- **Wi-Fi Protected Access 3 (WPA3)**
- **WPA3:** Modern standard using **SAE (Simultaneous Authentication of Equals)** to prevent brute-force attacks (Dragonfly Handshake).
- **AAA/Remote Authentication Dial-In User Service (RADIUS)**
- **802.1X/RADIUS:** Port-based network access control requiring individual authentication.
- **Cryptographic protocols**
- **Authentication protocols**

**Application security**

- **Input Validation:** Ensuring data matches expected types/lengths to prevent SQLi and XSS.
- **Secure Cookies:** Setting the "Secure" attribute (HTTPS only) and "HttpOnly" attribute (prevents JS access).
- **Static code analysis**
  - **Static (SAST):** Reviewing source code without running it (finds syntax/logic errors).
  - **Dynamic (DAST):** Testing the application while it's running (Fuzzing).
- **Code signing**
- **Code Signing:** Using digital signatures to verify the author and integrity of software.

**Sandboxing**

- **Sandboxing:** Running applications in isolated environments to prevent lateral movement.
**Monitoring**
