- ## 5.0 Network Troubleshooting 24%

  - **Goal of Domain 5**:
    - This domain covers how to approach, diagnose, and resolve a wide variety of network issues using structured methodologies and tools.
    - It represents the largest percentage of the exam and is vital for real-world technical troubleshooting.

  - **Things You Must Memorize**:
    - The 6-step troubleshooting process (Official CompTIA).
    - Common interface errors: CRC (corruption), Runts (<64 bytes), Giants (>1518 bytes).
    - DHCP/DNS failure symptoms (APIPA, can't resolve names).
    - Performance metrics: Latency, Jitter, Packet Loss, Throughput.
    - Hardware tools: TDR (copper), OTDR (fiber), Multimeter, Loopback.

- ### 5.1 Explain the troubleshooting methodology

  - **Step 1: Identify the Problem**:
    - Gather information: Logs, performance data.
    - Question users: Find out exactly what they are experiencing.
    - Identify symptoms: What is broken?
    - Determine if anything has changed: Recent updates, hardware moved?
    - Duplicate the problem if possible.
    - Approach multiple problems individually.
  - **Step 2: Establish a Theory of Probable Cause**:
    - Question the obvious (power, cables).
    - Consider multiple approaches: Top-to-bottom, Bottom-to-top (OSI model), or Divide and Conquer.
  - **Step 3: Test the Theory to Determine the Cause**:
    - If theory is confirmed, move to the next step.
    - If theory is not confirmed, establish a new theory or escalate the issue.
  - **Step 4: Establish a Plan of Action and Identify Potential Effects**:
    - Determine the exact steps to fix the issue.
    - Assess the impact (will this cause a broader outage?).
  - **Step 5: Implement the Solution or Escalate**:
    - Execute the plan.
    - Escalate to a senior tech if the plan fails or is too complex.
  - **Step 6: Verify Full System Functionality and Implement Preventive Measures**:
    - Ensure everything is working as expected.
    - Talk to the user to confirm their issue is resolved.
    - Implement changes to prevent the issue from happening again.
  - **Step 7: Document Findings, Actions, Outcomes, and Lessons Learned**:
    - Create a record in the knowledge base.
    - Crucial for future troubleshooting and trend analysis.

- ### 5.2 Given a scenario, troubleshoot common cabling and physical interface issues

  - **Physical Layer Issues**:
    - **Attenuation**: Signal loss over distance; exceeding cable length limits.
    - **Crosstalk (NEXT/FEXT)**: Signal bleeding between wire pairs.
    - **EMI/RFI**: Electromagnetic or Radio Frequency interference from external sources (motors, fluorescent lights).
    - **Open/Short**: A break in the wire (Open) or two wires touching (Short).
    - **Improper Termination**: Bad crimps, incorrect pinouts (T568A/B mismatch).
    - **Fiber Issues**: Bend radius exceeded, dirty connectors (most common fiber issue), TX/RX mismatch.
  - **Interface Errors**:
    - **CRC Errors**: Frames corrupted during transit (check cables and interference).
    - **Runts**: Frames too small; usually caused by collisions (Layer 2).
    - **Giants**: Frames too large; usually an MTU mismatch or a bad NIC.
    - **Drops**: Discarded packets due to congestion (buffer overflow) or errors.
    - **Error-Disabled**: A port shut down by the switch for security or error violations (e.g., BPDU Guard).

- ### 5.3 Given a scenario, troubleshoot common issues with network services

  - **DHCP Issues**:
    - **APIPA (169.254.x.x)**: Client didn't get a DHCP response.
    - **Exhaustion**: No more IPs left in the pool.
    - **Rogue DHCP**: An unauthorized server handing out bad info (gateway/DNS).
  - **DNS Issues**:
    - **Misconfiguration**: Wrong DNS server set on the client.
    - **DNS Poisoning**: Corrupted cache directing users to malicious sites.
  - **Switching/Routing Issues**:
    - **STP Loop**: Broadcast storm taking down the network; check for redundant paths without STP.
    - **VLAN Mismatch**: Trunk port configured differently on each end.
    - **Stale Routes**: Old info in the routing table causing packets to be dropped.
    - **MTU Mismatch**: Large packets being dropped or fragmented excessively.

- ### 5.4 Given a scenario, troubleshoot common performance issues

  - **Throughput vs. Bandwidth**: Bandwidth is theoretical max; Throughput is actual success rate.
  - **Latency**: Delay in data arrival; caused by distance or processing.
  - **Jitter**: Variation in delay; critical for VoIP and Video.
  - **Bottleneck**: A single slow component slowing down the entire path.
  - **Wireless Performance**:
    - **Interference**: Other electronics or neighboring Wi-Fi.
    - **Dead Zones**: Areas with no coverage; need more APs or better placement.
    - **AP Overload**: Too many clients on one radio.

- ### 5.5 Given a scenario, use the appropriate tool or protocol to solve networking issues

  - **Software/CLI Tools**:
    - **Ping**: Connectivity test (ICMP).
    - **Traceroute/Tracert**: Shows every hop in the path.
    - **Nslookup/Dig**: DNS troubleshooting.
    - **Netstat**: Shows active connections and port status on a host.
    - **IPConfig/Ifconfig/IP**: View/set interface configurations.
    - **Nmap**: Port scanner and network discovery.
    - **Tcpdump/Wireshark**: Packet capture and protocol analysis.
  - **Hardware Tools**:
    - **TDR (Time Domain Reflectometer)**: Finds the exact distance to a break/short in copper.
    - **OTDR (Optical TDR)**: Same as TDR but for fiber.
    - **Multimeter**: Tests voltage and continuity.
    - **Tone Generator & Probe (Fox and Hound)**: Traces a specific wire in a bundle.
    - **Wi-Fi Analyzer**: Shows signal strength and channel usage.
    - **Loopback Plug**: Tests if a physical port is working.
  - **Device Commands (Cisco-style)**:
    - **Show Interface**: Check for errors (CRC, drops).
    - **Show Route**: Check the routing table.
    - **Show MAC-Address-Table**: Check which devices are on which ports.
    - **Show VLAN**: Verify port assignments.
