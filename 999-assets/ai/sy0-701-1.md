# 1.0 General Security Concepts (12%)

## 1.1 Compare and contrast various types of security controls

Security controls are safeguards or measures taken to reduce risk to assets (data, physical property, computer systems).

### Categories
- **Technical (Logical):** Controls implemented via software, hardware, or firmware systems.
  - **Examples:** Firewalls, encryption, Intrusion Detection Systems (IDS), antivirus, authentication mechanisms, BIOS/UEFI settings.
  - **Pros/Cons:** Automated and scalable, but vulnerable to technical failures or software bugs.
- **Managerial (Administrative):** Strategic risk governance through policies and procedures (the "design" and "governance").
  - **Examples:** Risk assessments, security policies (AUP), hiring practices (background checks), security awareness training, vendor management.
  - **Pros/Cons:** Pivotal for strategic decision-making, but requires regular review and management commitment.
- **Operational:** Processes executed by people during daily operations.
  - **Examples:** Backup and recovery procedures, incident response, change management, physical security guards, awareness programs.
  - **Pros/Cons:** Addresses day-to-day human behavior, but vulnerable to human error and requires continuous oversight.
- **Physical:** Tangible, real-world measures protecting assets and safety.
  - **Examples:** Bollards, fences, locks, CCTV, security guards, access badges, fire suppression, motion sensors.
  - **Pros/Cons:** Protects against physical theft/damage, but does not protect against remote cyber threats.

### Control Types (Functional)
- **Preventive:** Stops a security incident before it occurs (proactive).
  - **Examples:** Firewall rules, locked doors, strong password policies, encryption, guard shacks.
- **Deterrent:** Discourages intrusion by warning of negative consequences or increasing perceived risk.
  - **Examples:** Warning signs ("No Trespassing"), visible security cameras, application splash screens, threat of demotion.
- **Detective:** Identifies and records events during or after occurrence (reactive).
  - **Examples:** Audit logs, security alarms, IDS, motion detectors, regularly patrolling guards.
- **Corrective:** Mitigates damage and restores systems after incidents (correcting the problem).
  - **Examples:** Restoring from backups, antivirus quarantining/removing malware, patching a vulnerability after a breach, fire extinguishers.
- **Compensating:** Alternative substitute when primary control is not feasible or sufficient.
  - **Examples:** If you can't encrypt an old system, use strict physical isolation (locked room); using a generator during a power outage.
- **Directive:** Mandates compliance through administrative rules, regulations, or guidance.
  - **Examples:** Acceptable Use Policy (AUP), security awareness training, signs ("Authorized Personnel Only").

> **Exam Tip:** Be prepared to categorize a specific control by both Category and Type. (e.g., A security guard is both a *Physical* category and can be *Preventive*, *Deterrent*, or *Detective*).

## 1.2 Summarize fundamental security concepts

### Confidentiality, Integrity, and Availability (CIA Triad)
The fundamental goals of cybersecurity (sometimes called the AIC Triad).
- **Confidentiality:** Preventing unauthorized access or disclosure of data.
  - **Techniques:** Encryption, access controls, MFA.
- **Integrity:** Ensuring data remains accurate and unaltered.
  - **Techniques:** Hashing, digital signatures, file permissions, certificates.
- **Availability:** Ensuring data and systems are accessible when needed.
  - **Techniques:** Redundancy (RAID, Load Balancing), fault tolerance, patching, backups.

### Non-repudiation
Guarantees that a subject cannot deny having performed an action.
- **Techniques:** Digital signatures (signed with a private key), logging systems.
- **Example:** A digitally signed email provides proof of origin and proof that the sender sent it.

### Authentication, Authorization, and Accounting (AAA)
- **Identification:** Claiming an identity (e.g., username).
- **Authentication:** Proving you are who you say you are ("Who are you?").
  - **Authenticating People:** Passwords, biometrics (fingerprint/face), smartcards, OTP apps.
  - **Authenticating Systems:** Digitally signed certificates, keys.
- **Authorization:** Determining access rights and permissions ("What can you do?").
  - **Authorization Models:** Structured rules like Role-Based Access Control (RBAC), Attribute-Based Access Control (ABAC), Mandatory Access Control (MAC).
- **Accounting:** Tracking and recording activities for auditing ("What did you do?").
  - **Techniques:** Log review, audit trails, monitoring access attempts.

### Gap Analysis
Comparing the current security posture against the desired state or industry standards.
- **Goal:** Identify weaknesses ("gaps") and create action plans to reach the desired baseline (e.g., NIST, ISO).

### Zero Trust
A holistic security model based on the principle: **"Never trust, always verify."**
- **Core Principles:** No implicit trust (even inside the network), assume breach, least privilege.
- **Control Plane (The "Brain"):** Orchestrates access decisions and policy management.
  - **Adaptive Identity:** Authentication requirements adjust based on risk context (location, IP, device health).
  - **Threat Scope Reduction:** Minimizing the potential attack surface.
  - **Policy-driven Access Control:** Access granted strictly based on defined rules.
  - **Policy Engine:** Evaluates access requests against policies (the decision maker).
  - **Policy Administrator:** Establishes/terminates the connection based on the Engine's decision.
- **Data Plane (The "Action"):** Where actual application data flow occurs.
  - **Implicit Trust Zones:** Trusted network areas; these are **eliminated** in a Zero Trust architecture.
  - **Subject/System:** The entity requesting access.
  - **Policy Enforcement Point (PEP):** Gatekeeper that intercepts traffic to enforce decisions (e.g., firewall, gateway).

### Physical Security
Tangible measures to protect assets.
- **Barriers:** Bollards (prevent vehicle ramming), fencing (perimeter barrier), access control vestibules (mantraps/double-door systems to prevent tailgating).
- **Monitoring:** Video surveillance (CCTV), security guards.
- **Access:** Access badges, lighting (deterrent/facial recognition helper).
- **Sensors:**
  - **Infrared:** Detects heat signatures.
  - **Pressure:** Detects weight (mats, windows).
  - **Microwave:** Detects movement across large areas using radio waves.
  - **Ultrasonic:** Uses high-frequency sound waves.

### Deception and Disruption Technology
Techniques to confuse, trap, or slow attackers.
- **Honeypot:** Single decoy system/device to lure attackers.
- **Honeynet:** A fake network of honeypots simulating a real environment.
- **Honeyfile:** Decoy file (e.g., "passwords.txt") that triggers alerts when accessed.
- **Honeytoken:** Traceable data (fake API keys, email addresses) used to track attacker activity if stolen.

## 1.3 Explain the importance of change management processes and the impact to security

Change management ensures modifications (software upgrades, firewall changes) are structured and secure to avoid introducing vulnerabilities.

### Business Processes Impacting Security Operation
- **Approval Process:** Formal authorization required before implementation.
- **Ownership:** Designating an accountable individual for an asset/change.
- **Stakeholders:** Engaging all affected parties for feedback and awareness.
- **Impact Analysis:** Assessing potential security consequences before a change.
- **Test Results:** Proof that changes work correctly and don't break security.
- **Backout Plan:** A documented procedure to revert changes if they fail (Rollback).
- **Maintenance Window:** Scheduled authorized timeframe for changes to minimize disruption.
- **Standard Operating Procedure (SOP):** Step-by-step instructions for routine changes.

### Technical Implications
- **Allow lists / Deny lists:** Updating lists that permit or block traffic/software.
- **Restricted Activities:** Prohibiting high-risk actions during specific times.
- **Downtime:** Period when services are unavailable; must be minimized and secured.
- **Service/Application Restart:** Securely restarting components to apply updates.
- **Legacy Applications:** Older software that might be incompatible or unpatchable.
- **Dependencies:** Ensuring changes don't break other required components.

### Documentation & Version Control
- **Updating Diagrams:** Keeping network/logical architecture visuals current.
- **Updating Policies/Procedures:** Modifying rules to reflect new realities.
- **Version Control:** Tracking and managing changes to files/code; critical for forensics.

## 1.4 Explain the importance of using appropriate cryptographic solutions

### Public Key Infrastructure (PKI)
Framework for managing digital keys and certificates to ensure trust.
- **Public Key:** Sharable key used for encryption or signature verification.
- **Private Key:** Secret key used for decryption or creating digital signatures.
- **Key Escrow:** Storing keys with a trusted third party for recovery (e.g., in legal or lost-access scenarios).

### Encryption
- **Levels:**
  - **Full-disk (FDE):** Encrypts the entire physical drive (TPM usually stores the key).
  - **Partition/Volume:** Encrypts specific logical sections of a drive.
  - **File/Database/Record:** Encrypts individual files or specific database entries.
- **Transport/Communication:** Encrypting data-in-transit (e.g., HTTPS/TLS, VPN).
- **Symmetric:** One key for both encryption and decryption (fast, e.g., AES).
- **Asymmetric:** Uses public/private key pairs (slower, e.g., RSA, ECC).
- **Key Exchange:** Securely swapping keys (e.g., Diffie-Hellman).
- **Algorithms:** Mathematical formulas (AES, RSA, ECC, etc.).
- **Key Length:** Number of bits (Entropy); longer keys are harder to crack.

### Cryptographic Tools
- **Trusted Platform Module (TPM):** Motherboard chip that stores keys and ensures boot integrity.
- **Hardware Security Module (HSM):** Dedicated physical appliance for high-volume secure key management.
- **Key Management System:** Software for managing the full key lifecycle.
- **Secure Enclave:** CPU-isolated area protecting sensitive memory (e.g., Apple's T2).

### Obfuscation & Data Protection
- **Steganography:** Hiding secret data within innocent-looking files (e.g., an image).
- **Tokenization:** Replacing sensitive data with non-sensitive unique symbols (tokens).
- **Data Masking:** Hiding specific characters (e.g., XXXXX-1234).

### Core Cryptographic Concepts
- **Hashing:** One-way conversion to a fixed string (Integrity).
- **Salting:** Adding random data to passwords before hashing (prevents rainbow table attacks).
- **Digital Signatures:** Cryptographic proof of origin and integrity (Authentication + Non-repudiation).
- **Key Stretching:** Making weak keys stronger by repeating hashing (e.g., PBKDF2, bcrypt).
- **Blockchain:** Decentralized, immutable open public ledger.

### Certificates
Digital documents binding a key to an identity.
- **Certificate Authority (CA):** Trusted third party that issues certificates.
- **Certificate Revocation List (CRL):** A list of revoked certificates published by the CA.
- **Online Certificate Status Protocol (OCSP):** Real-time valid-check; **OCSP Stapling** lets the server cache the status to save resources.
- **Self-signed vs. Third-party:** Signed by owner vs. signed by a trusted CA.
- **Root of Trust:** The ultimate, foundational trust anchor in the PKI.
- **Certificate Signing Request (CSR):** Sent to CA to apply for a certificate.
- **Wildcard:** Certificate covering a domain and all its subdomains (e.g., `*.example.com`).
