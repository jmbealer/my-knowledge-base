# 5.0 Network Troubleshooting (24%)

## 5.1 Explain the network troubleshooting methodology

CompTIA defines a standard 7-step process for resolving technical issues.

1. **Identify the Problem:**
    - Gather information (question users, identify symptoms).
    - Determine if anything has changed.
    - Duplicate the problem if possible.
    - Identify the scope (is it one person or everyone?).
2. **Establish a Theory of Probable Cause:**
    - Question the obvious.
    - Consider multiple approaches (Top-to-bottom vs. Bottom-to-top OSI model).
3. **Test the Theory to Determine the Cause:**
    - If the theory is confirmed, move to the next step.
    - If the theory is disproved, establish a new theory or escalate.
4. **Establish a Plan of Action and Identify Potential Effects:**
    - Plan how to fix it without breaking other things.
5. **Implement the Solution or Escalate:**
    - Carry out the plan or move the ticket to a senior engineer.
6. **Verify Full System Functionality:**
    - Ensure everything works correctly and implement preventive measures to stop it from happening again.
7. **Document Findings, Actions, Outcomes, and Lessons Learned:**
    - Record the "fix" in the knowledge base for future reference.

## 5.2 Given a scenario, troubleshoot common cable connectivity issues

### Physical Toolset
- **Cable Tester:** Checks for continuity and correct pinouts.
- **Tone Generator & Probe:** Locates a specific cable in a messy bundle (Fox and Hound).
- **Multimeter:** Checks voltage and resistance.
- **Optical Time-Domain Reflectometer (OTDR):** Finds the exact location of a break in a fiber optic cable.
- **Time-Domain Reflectometer (TDR):** Same as OTDR but for copper.
- **Visual Fault Locator (VFL):** A simple laser to find breaks or bends in fiber.

### Common Cable Issues
- **Attenuation:** Signal loss over distance (exceeding length limits).
- **Crosstalk (NEXT/FEXT):** Signal "bleeding" from one wire pair to another.
- **Open / Short:** Broken wire (Open) or wires touching (Short).
- **Split Pairs:** Wires connected correctly but paired incorrectly (causes massive interference).
- **Bad Connectors:** Poorly crimped RJ45 or damaged fiber tips (check for dirty tips with a fiber scope).
- **Bend Radius:** Exceeding the curve limit of fiber, causing signal loss.

## 5.3 Given a scenario, use the appropriate tool to troubleshoot connectivity issues

### Software Command-Line Tools
- **ping:** Tests basic connectivity (ICMP).
- **tracert / traceroute:** Shows the path (hops) a packet takes to a destination.
- **nslookup / dig:** Troubleshoots DNS issues (resolving names to IPs).
- **ipconfig / ifconfig / ip addr:** Shows local IP configuration (IP, Mask, Gateway).
- **netstat:** Shows active connections and listening ports on a device.
- **nmap:** Port scanner; identifies open ports and services on a remote host.
- **route:** Views or modifies the local routing table.
- **arp:** Views the ARP cache (IP to MAC mappings).
- **pathping / mtr:** Combines ping and traceroute for long-term statistics over a path.
- **tcpdump / wireshark:** Packet capture and analysis.

## 5.4 Given a scenario, troubleshoot common wireless connectivity issues

### Signal & Interference
- **Interference:** Other devices (microwaves, cordless phones) or other Wi-Fi networks using the same channel.
- **Multipath Distortion:** Radio signals reflecting off surfaces and arriving at different times.
- **Absorption / Refraction:** Materials (concrete, water, glass) blocking or bending the signal.
- **Distance / Path Loss:** Being too far from the Access Point.

### Configuration Issues
- **Incorrect SSID:** Trying to connect to the wrong network.
- **Authentication Issues:** Wrong password, expired certificate, or RADIUS server downtime.
- **Latency / Jitter:** Caused by congestion or poor signal; critical for VoIP/Video.
- **Overcapacity:** Too many clients connected to a single AP.

## 5.5 Given a scenario, troubleshoot general networking issues

### Configuration Mismatches
- **Speed / Duplex Mismatch:** One side is 1 Gbps/Full and the other is 100 Mbps/Half (causes high collisions/slowness).
- **VLAN Mismatch:** Devices are on different VLANs and cannot communicate without a router.
- **MTU Mismatch:** Packets are too large for a link; results in fragmentation or dropped packets (ICMP "Destination Unreachable").
- **Incorrect IP / Mask / Gateway:** Basic addressing errors prevent any communication.

### Network Services Issues
- **DNS Failure:** Can ping IPs but cannot browse websites.
- **DHCP Exhaustion:** No more IPs available in the scope; clients get APIPA addresses (169.254.x.x).
- **Default Gateway Issue:** Can talk to local devices but cannot reach the internet/other subnets.
- **ACL / Firewall Block:** Traffic is being explicitly dropped by a security rule.
- **Unresponsive Service:** The network is fine, but the target application/server is down.
