# 4.0 Security Operations (28%)

## 4.1 Given a scenario, apply common security techniques to computing resources

### Secure Baselines
- **Establish:** Define minimum security requirements for a system (e.g., standard OS settings, required patches).
- **Deploy:** Use automation (Group Policy, MDM) to apply baselines across thousands of devices.
- **Maintain:** Regularly audit and update baselines as new vulnerabilities or software versions emerge.

### Hardening Targets
- **Workstations/Servers:** Disable unnecessary services, close unused ports, use host-based firewalls and EDR.
- **Network Devices (Routers/Switches):** Change default credentials, use SSH instead of Telnet, disable unused ports.
- **Specialized Systems:** 
  - **ICS/SCADA:** Require extreme segmentation and often air-gapping.
  - **IoT:** Change default passwords and isolate on separate VLANs.
  - **RTOS/Embedded:** Run minimum services and use secure communication protocols.

### Wireless & Mobile Security
- **Site Surveys:** Using heat maps to identify signal strength and interference.
- **Mobile Deployment Models:**
  - **BYOD (Bring Your Own Device):** Employee-owned; difficult to secure but saves costs.
  - **COPE (Corporate Owned, Personally Enabled):** Organization buys and controls the device but allows personal use.
  - **CYOD (Choose Your Own Device):** Similar to COPE but with a choice of hardware.
- **Wireless Security Settings:**
  - **WPA3:** Modern standard using **SAE (Simultaneous Authentication of Equals)** to prevent brute-force attacks (Dragonfly Handshake).
  - **802.1X/RADIUS:** Port-based network access control requiring individual authentication.

### Application Security
- **Input Validation:** Ensuring data matches expected types/lengths to prevent SQLi and XSS.
- **Secure Cookies:** Setting the "Secure" attribute (HTTPS only) and "HttpOnly" attribute (prevents JS access).
- **Code Analysis:**
  - **Static (SAST):** Reviewing source code without running it (finds syntax/logic errors).
  - **Dynamic (DAST):** Testing the application while it's running (Fuzzing).
- **Code Signing:** Using digital signatures to verify the author and integrity of software.
- **Sandboxing:** Running applications in isolated environments to prevent lateral movement.

## 4.2 Explain the security implications of proper hardware, software, and data asset management

### Asset Lifecycle
- **Acquisition/Procurement:** Ensuring vendors are vetted and hardware is authentic (avoiding counterfeit components).
- **Assignment/Accounting:** Assigning owners to assets and classifying them (e.g., Laptop #402 is assigned to the CFO).
- **Inventory/Enumeration:** Maintaining a real-time list of all hardware and software in the environment.
- **Disposal/Decommissioning:**
  - **Sanitization:** Wiping data so it cannot be recovered (Clearing/Purging).
  - **Degaussing:** Removing the magnetic field of a drive (renders it unusable).
  - **Physical Destruction:** Shredding or incinerating drives.
  - **Certification:** Obtaining a "Certificate of Destruction" from a 3rd party.

## 4.3 Explain various activities associated with vulnerability management

### Identification & Analysis
- **Identification:**
  - **Vulnerability Scans:** Passive (credentialed vs. non-credentialed).
  - **Threat Feeds:** OSINT, proprietary feeds, and dark web monitoring.
  - **Bug Bounties:** Rewarding researchers for disclosing vulnerabilities.
- **Scoring (CVSS):** Common Vulnerability Scoring System (0-10 scale).
  - **Base Score:** Represents the intrinsic qualities of a vulnerability.
  - **Environmental Score:** Adjusts the score based on the organization's specific context.
- **CVE (Common Vulnerabilities and Exposures):** A unique identifier for a specific known vulnerability (e.g., CVE-2023-XXXX).

### Response & Remediation
- **Patching:** The primary method of fixing vulnerabilities.
- **Compensating Controls:** Temporary measures used if a patch cannot be applied immediately (e.g., blocking a port).
- **Exceptions:** Formally documenting when a risk is accepted without remediation.
- **Validation:** Rescanning after remediation to confirm the fix was successful.

## 4.4 Explain security alerting and monitoring concepts and tools

### Monitoring Activities
- **Log Aggregation:** Collecting logs from firewalls, servers, and apps into a central location.
- **SIEM (Security Information and Event Management):** Real-time analysis, correlation, and long-term storage of logs.
- **Alert Tuning:** Reducing false positives to prevent "alert fatigue."

### Tools
- **SCAP (Security Content Automation Protocol):** A standard for sharing security data and verifying configurations.
- **Benchmarks (CIS):** Industry-standard best practices for system hardening.
- **NetFlow:** Analyzing IP traffic patterns (Who, What, When, Where) without seeing the payload.
- **SNMP Traps:** Real-time alerts sent from network devices to a management station.

## 4.5 Given a scenario, modify enterprise capabilities to enhance security

### Network Enhancements
- **Firewall Rules:** Updating ACLs to restrict traffic based on least privilege.
- **IDS/IPS:** Tuning signatures to detect new attack patterns.
- **Web Filtering:** Blocking sites by category or reputation.
- **Email Security:**
  - **SPF (Sender Policy Framework):** List of authorized IP addresses allowed to send mail for a domain.
  - **DKIM (DomainKeys Identified Mail):** Digital signature attached to emails to verify the sender.
  - **DMARC:** Instructions to the receiver on how to handle mail that fails SPF or DKIM.

### Endpoint & Data Protection
- **EDR (Endpoint Detection and Response):** Real-time monitoring and automated response on the device.
- **XDR (Extended Detection and Response):** Merging data from endpoints, networks, and cloud for a holistic view.
- **DLP (Data Loss Prevention):** Preventing sensitive data from leaving the network (via email, USB, or cloud).
- **NAC (Network Access Control):** Health checks (posture assessment) before allowing a device onto the network.

## 4.6 Given a scenario, implement and maintain identity and access management

### Federation & SSO
- **SSO (Single Sign-On):** Log in once, access everything.
- **SAML (Security Assertions Markup Language):** XML-based framework for exchanging authentication/authorization data (common in Enterprise SSO).
- **OAuth:** Authorization framework (delegating access without sharing passwords).
- **OpenID Connect:** Identity layer built on top of OAuth 2.0 (Authentication).

### Access Control Models
- **MAC (Mandatory):** Access based on security labels and clearances (Military/Government).
- **DAC (Discretionary):** Resource owner decides who has access (Flexible but risky).
- **RBAC (Role-Based):** Access based on job function (Admin, HR, Sales).
- **ABAC (Attribute-Based):** Access based on complex attributes (Time of day, IP address, user department).

### MFA (Multifactor Authentication)
- **Factors:**
  - **Something you know:** Password, PIN.
  - **Something you have:** Smart card, Hardware token, Smartphone.
  - **Something you are:** Fingerprint, Face scan, Retina scan.
  - **Somewhere you are:** GPS location, IP geofencing.

### Privileged Access Management (PAM)
- **Just-in-Time (JIT):** Granting elevated permissions only when needed and for a limited duration.
- **Password Vaulting:** Centrally storing and rotating administrative passwords.

## 4.7 Explain the importance of automation and orchestration related to secure operations

- **Benefits:** Efficiency, consistent baselines, faster reaction time, and acting as a "workforce multiplier."
- **Considerations:** High initial cost, complexity, single points of failure (if the automation tool breaks), and technical debt.

## 4.8 Explain appropriate incident response activities

### Incident Response Process
1. **Preparation:** Building the team and tools.
2. **Detection:** Identifying the incident.
3. **Analysis:** Determining the scope and impact.
4. **Containment:** Stopping the spread (Isolating systems).
5. **Eradication:** Removing the root cause (Deleting malware).
6. **Recovery:** Restoring systems to normal operation.
7. **Lessons Learned:** Post-incident review to improve future response.

### Digital Forensics
- **Legal Hold:** Preserving all potentially relevant data for legal action.
- **Chain of Custody:** Documented history of who handled evidence and when.
- **E-Discovery:** Identifying and collecting electronic information for legal requests.

## 4.9 Given a scenario, use data sources to support an investigation

- **Log Data:** Firewall (blocked traffic), App (user actions), OS (logons), IPS (attack alerts).
- **Metadata:** "Data about data" (file creation dates, email headers).
- **Packet Captures:** Recording raw network traffic for deep forensic analysis.
