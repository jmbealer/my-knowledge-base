# 3.0 Network Operations (19%)

## 3.1 Explain the purpose of organizational processes and procedures

### Documentation
- **Diagrams:**
    - **Physical Diagram:** Shows real-world layout (racks, cabling, actual devices).
    - **Logical Diagram:** Shows data flow, subnets, VLANs, and IP addresses.
    - **Rack Diagram:** Visualizes the layout of equipment within a rack (measured in U).
    - **Network Diagrams (by Layer):**
        - **Layer 1:** Physical cabling and port connections.
        - **Layer 2:** Switches, VLANs, and Spanning Tree topology.
        - **Layer 3:** IP addresses and routing paths.
- **Asset Inventory:**
    - **Hardware/Software:** Tracking versions, vendors, and quantities.
    - **Licensing/Warranty:** Managing renewals and support status.
- **IPAM (IP Address Management):** Tools for tracking IP address usage, DHCP scopes, and DNS records.
- **SLA (Service Level Agreement):** Contractual performance standards (uptime, response time).
- **Wireless Survey/Heat Map:** Visual representation of signal strength and coverage.

### Life-Cycle Management
- **End-of-Life (EOL):** Vendor stops selling the product.
- **End-of-Support (EOS):** Vendor stops providing patches or technical help.
- **Decommissioning:** Securely removing and wiping assets from the network.

### Change & Configuration Management
- **Change Management:** A formal process for requesting, approving, and documenting modifications to the environment.
- **Baseline (Golden) Configuration:** A standard, known-good configuration used for new deployments.
- **Configuration Drift:** When a system's settings deviate from the established baseline over time.

## 3.2 Given a scenario, use network monitoring technologies

### Monitoring Methods
- **SNMP (Simple Network Management Protocol):**
    - **Components:** Managed device, Agent, NMS (Network Management System).
    - **MIB (Management Information Base):** The database of objects a device can report.
    - **Operations:**
        - **Get:** NMS asks the device for information.
        - **Trap:** Device proactively sends an alert to the NMS (unsolicited).
    - **Versions:**
        - **v2c:** Community-string based (insecure, cleartext).
        - **v3:** Supports Authentication and Encryption (Secure).
- **Flow Data (NetFlow/sFlow/IPFIX):** Provides traffic statistics (source/destination IP, ports, volume) without capturing actual payloads. Useful for "Top Talkers" analysis.
- **Packet Capture (pcap):** Captures raw traffic for deep analysis (Wireshark).
- **Log Aggregation:**
    - **Syslog:** A standard for message logging.
    - **SIEM (Security Information and Event Management):** Centralizes and correlates logs for real-time analysis and alerting.

### Monitoring Solutions
- **Performance Monitoring:** Tracks CPU, RAM, and Bandwidth utilization.
- **Availability Monitoring:** Ensuring systems are "up" (Ping/ICMP).
- **Port Mirroring (SPAN/RSPAN):** Copying traffic from one port to another for analysis.

## 3.3 Explain Disaster Recovery (DR) concepts

### DR Metrics
- **RPO (Recovery Point Objective):** The maximum tolerable amount of data loss (measured in time). "How much data can we afford to lose?"
- **RTO (Recovery Time Objective):** The target time to restore a system after failure. "How long can we be down?"
- **MTTR (Mean Time to Repair):** The average time required to fix a failed component.
- **MTBF (Mean Time Between Failures):** A measure of system reliability/longevity.

### DR Sites
- **Cold Site:** Basic infrastructure (power, cooling), no hardware or data. Recovery takes days/weeks.
- **Warm Site:** Has hardware, but needs final configuration and data restoration. Recovery takes hours/days.
- **Hot Site:** A fully operational duplicate of the production environment with synchronized data. Recovery is near-instant.

### Availability Models
- **Active-Active:** Both systems handle traffic; provides both load balancing and redundancy.
- **Active-Passive:** One system is standby and only takes over if the primary fails.
- **Testing:**
    - **Tabletop Exercise:** Discussion-based walkthrough of the DR plan.
    - **Validation Test:** Actual failover testing of systems and backups.

## 3.4 Given a scenario, implement IPv4 and IPv6 network services

### Dynamic Addressing (DHCP)
- **Scope:** The range of IP addresses available to lease.
- **Lease Time:** How long a client can use an IP before needing to renew.
- **Reservation:** Mapping a specific IP to a MAC address (Permanent lease).
- **Options:** Additional info like Default Gateway (Option 3) and DNS (Option 6).
- **DHCP Relay / IP Helper:** Forwards DHCP requests across different subnets.

### Name Resolution (DNS)
- **Record Types:**
    - **A:** Host name to IPv4.
    - **AAAA:** Host name to IPv6.
    - **CNAME:** Alias (canonical name).
    - **MX:** Mail exchange (points to mail server).
    - **TXT:** Text (used for SPF/DKIM verification).
    - **PTR:** Reverse lookup (IP to name).
- **DNS Security:**
    - **DNSSEC:** Adds digital signatures to DNS records for integrity.
    - **DoH / DoT:** Encrypts DNS queries (HTTPS or TLS) to prevent eavesdropping.
- **Zones:**
    - **Forward Lookup:** Name to IP.
    - **Reverse Lookup:** IP to Name.
    - **Authoritative:** The server that holds the master copy of the zone data.

### Time Protocols
- **NTP:** Synchronizes clocks across the network.
- **PTP (Precision Time Protocol):** Sub-microsecond accuracy (used in specialized industrial/financial systems).

## 3.5 Compare and contrast network access and management methods

### VPN Types
- **Site-to-Site:** Connects two whole networks (e.g., Branch office to HQ).
- **Client-to-Site:** A single device connecting to the corporate network (Remote access).
    - **Full Tunnel:** All client traffic goes through the VPN.
    - **Split Tunnel:** Only corporate traffic goes through the VPN; internet traffic goes out locally.
- **Clientless VPN:** Browser-based access (usually SSL/TLS) without installing a local client.

### Remote Management
- **SSH:** Secure, encrypted CLI access.
- **RDP/VNC:** Graphical remote desktop access.
- **Jump Box / Jump Host:** A hardened server used as a single entry point to manage other servers in a secure zone.
- **Out-of-Band (OOB) Management:** Managing devices through a dedicated network or physical console port, separate from the main data network.
